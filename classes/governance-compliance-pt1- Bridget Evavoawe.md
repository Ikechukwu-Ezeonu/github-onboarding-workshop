# Key Concepts I Learned

- Azure Policy helps organizations enforce governance by ensuring Azure resources comply with organizational standards and regulatory requirements.
- Policies can be assigned at different levels, such as management groups, subscriptions, resource groups, or individual resources, depending on the level of control required.
- Azure Policy evaluates resources to determine whether they comply with assigned rules and identifies resources that violate those rules.
- I learned that Azure Policy can evaluate resources both when they are created or updated and through periodic compliance scans.
- If a resource does not comply with an assigned policy, Azure can either prevent the action, audit the resource, or allow remediation depending on how the policy is configured.
- Resource Locks help prevent accidental deletion or modification of critical Azure resources by applying either a **Delete** lock or a **Read-only** lock.
- Microsoft Defender for Cloud provides continuous security monitoring, identifies security risks, and recommends actions to improve an organization's security posture.
- One framework discussed during the session focused on three important areas of cloud governance:

  - **Identity** – controlling who has access to Azure resources.
  - **Network** – controlling communication between resources.
  - **Monitoring** – tracking configuration changes and security events across the environment.

# My Takeaways

This session showed me that securing an Azure environment involves more than assigning permissions. Effective governance also requires enforcing policies, protecting critical resources with locks, continuously monitoring the environment, and reviewing compliance regularly. I also learned that Azure Policy plays an important role in maintaining consistency across cloud resources while Defender for Cloud helps organizations proactively identify and address security risks.
